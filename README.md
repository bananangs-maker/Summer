# MOTION — 운동 기록 앱

디터 람스의 절제된 제품 디자인 원칙에서 영감을 받은 개인용 운동 기록 앱입니다. 한국어 화면, 라이트/다크 전환, 모바일 대응. HTML/CSS/JavaScript 화면과 Python 서버, Supabase Postgres 저장소로 구성합니다. 로그인 없이 하나의 공용 기록을 사용합니다.

## 무료 배포: Render + Supabase

**Render Free 웹 서비스 + Supabase Free Postgres** 구성입니다. 유료 디스크나 Render 유료 DB를 만들지 않습니다. 무료 플랜의 사용량 제한 안에서 사용합니다. 이번 작업에서 외부 계정 생성·실제 배포·결제는 하지 않았습니다.

### 1. Supabase 준비

1. Supabase의 **Free 조직**에서 프로젝트 하나를 생성합니다. 가까운 리전을 선택하고 DB 비밀번호를 보관합니다.
2. 프로젝트 상단 **Connect → Session pooler → URI**를 선택해 연결 문자열을 복사합니다. 일반적으로 포트는 `5432`입니다. Session pooler는 IPv4 환경에서도 사용 가능합니다. 유료 IPv4 추가 기능은 필요하지 않습니다.
3. `[YOUR-PASSWORD]` 자리에 DB 비밀번호를 넣습니다. `@`, `#`, `:`, `/`, `%` 같은 특수문자는 URL 인코딩해야 합니다. 비밀번호를 채팅이나 GitHub에 게시하지 마세요.
4. 이 문자열은 다음 단계에서 Render의 서버 환경변수 **DATABASE_URL**에만 입력합니다. Supabase anon key나 service_role key는 사용하지 않습니다.

### 2. Render 배포

**이 폴더 안의 파일들을 GitHub 저장소 루트에 올려주세요.** `server.py`, `storage.py`, `requirements.txt`, `render.yaml`, `static/`가 루트에 있어야 합니다.

1. Render에서 **New → Blueprint**로 해당 GitHub 저장소를 연결합니다.
2. `render.yaml`의 웹 서비스 플랜이 **Free**인지 확인합니다. Disk 항목은 없습니다.
3. 입력을 요청하는 **DATABASE_URL**에 Supabase Session pooler URI를 넣고 배포합니다.
4. 처음 시작할 때 서버가 `motion_private` 스키마와 기록 테이블을 자동 생성합니다. Supabase SQL Editor에서 별도 SQL을 실행할 필요는 없습니다. 연결 문자열의 기본 postgres 계정이 생성 권한을 가져야 합니다.
5. 발급된 `https://서비스명.onrender.com`에서 시작 체중·목표 체중·시작일을 설정합니다.
6. 설정·백업에서 원하는 풀업·푸쉬업 루틴 위치를 선택합니다.

수동 Web Service 생성 시:

| 항목 | 값 |
|---|---|
| Instance Type | **Free** |
| Runtime | Python 3 |
| Build Command | `pip install -r requirements.txt` |
| Start Command | `gunicorn server:application --bind 0.0.0.0:$PORT --workers 1 --threads 4 --timeout 60` |
| 환경 변수 | `DATABASE_URL` = Supabase Session pooler URI |
| Disk | **추가하지 않음** |
| Health Check Path | `/health` |

### 기록 보존과 무료 플랜 동작

- 기록은 Render의 임시 파일이 아닌 **Supabase Postgres**에 저장됩니다. Render가 재시작·재배포돼도 같은 Supabase 프로젝트를 연결하면 기록이 유지됩니다.
- Render에서 DATABASE_URL이 누락되면 서버가 명시적으로 시작을 중단합니다. 임시 SQLite로 몰래 저장하지 않습니다.
- Render Free는 일정 시간 미사용 시 잠들고 재접속 때 기동 시간이 생깁니다. Supabase Free도 비활성 프로젝트를 일시 중지할 수 있습니다. 중지됐다면 Supabase 대시보드에서 재개한 후 다시 연결합니다.
- 무료 제공량·휴면 정책은 공급자 정책을 따릅니다. 유료 플랜 업그레이드나 유료 옵션 추가는 필요하지 않습니다.
- 기존 SQLite 버전에서 기록을 썼다면 **JSON 백업 → 새 버전의 백업 복원**으로 옮깁니다. 저장소가 달라져도 자동 이전되지는 않습니다.
- 서버는 TLS 연결을 사용하고 비밀번호를 브라우저에 전달하지 않습니다. private 스키마와 RLS를 설정하며 Supabase Data API에 테이블을 노출할 필요가 없습니다. DATABASE_URL은 서버 비밀 값으로만 보관합니다.
- 로그인은 요청대로 없습니다. 앱 주소를 아는 사람은 앱 API로 기록을 조회·수정할 수 있습니다. DB 비밀번호를 숨기는 것과 앱에 로그인하지 않는 것은 별개입니다.
- 여러 기기의 동시 수정은 원자적 revision 비교로 보호합니다. 충돌하면 새로고침 후 다시 기록해주세요.

문제 해결:

| 증상 | 확인할 항목 |
|---|---|
| DATABASE_URL 누락 오류 | Render → Environment에 입력 후 재배포 |
| DB 연결 실패 | Supabase 휴면 상태, DB 비밀번호, Session pooler URI, 허용 IP 설정 확인 |
| IPv6/네트워크 연결 오류 | Direct connection 대신 Session pooler URI 사용 |
| 비밀번호 특수문자 오류 | 비밀번호 부분만 URL 인코딩 |
| 첫 화면 로딩이 느림 | Render 무료 인스턴스가 깨는 중일 수 있음 |

## 로컬 실행

Python 3.12 이상. 개발 서버는 외부 패키지 없이 실행할 수 있습니다.

```bash
python server.py
```

브라우저에서 `http://localhost:8000`을 엽니다. HTML 파일을 더블클릭하는 대신 서버를 통해 열어야 기록 저장과 계산이 동작합니다. 로컬에서 DATABASE_URL이 없을 때만 개발용 SQLite DB가 `data/motion.sqlite3`에 생성됩니다. DATABASE_URL이 있으면 로컬에서도 Supabase를 사용합니다. `.env.example`은 입력 형식 참고용이며 `.env` 자동 로딩은 하지 않습니다. `DATA_DIR`로 변경할 수 있습니다. 서버에는 테스트 기록이 포함되어 있지 않습니다.

## 확정된 동작

- 종목: 러닝, 배드민턴, 풀업, 푸쉬업.
- 운동 종료 후 세트별 실제 횟수를 한 번에 입력. 총횟수 자동 합산.
- 시간: 맨몸운동 선택 입력, 유산소 필수. 러닝은 거리 필수, 페이스 자동 계산.
- 루틴: 풀업 1~38주, 푸쉬업 4~6주·Day 1~3·3개 난이도 열. 제공 이미지에서 전사. 푸쉬업 마지막 세트는 목표 이상(+).
- 현재 위치는 언제든 수동 선택. 클리어를 직접 체크했을 때만 다음 단계로 이동. 프로그램 마지막 단계에서는 현재 위치 유지.
- 과거 기록을 수정·삭제해도 현재 루틴 선택을 자동 되돌리지 않음. 필요하면 설정에서 직접 조정.
- 주간 필수: 월·수·금·일 풀업과 푸쉬업 모두, 화·목·토 러닝/배드민턴 중 하나 이상.
- 한국 시간 기준 다음 날 04:00 정산. 조회할 때 전 기간을 재계산하므로 별도 cron이 필요하지 않음.
- 과거 기록 수정 시 점수와 가상 체중도 재계산. 시작일 이전 감점 없음.
- JSON 백업·복원 및 CSV 내보내기. 정기적으로 JSON 백업을 따로 보관하세요.
- 테마는 기기의 브라우저에 저장. 운동 기록은 서버에 저장.

## 점수 규칙

| 조건 | XP |
|---|---:|
| 맨몸운동일 두 종목 모두 | +100 |
| 맨몸운동일 한 종목 누락 | −40 |
| 맨몸운동일 두 종목 누락 | −80 |
| 맨몸운동일 필수 충족 후 추가 유산소 | 종목당 +25 |
| 유산소일 한 종목 이상 | +100 |
| 유산소일 두 종목 | +125 합계 |
| 유산소일 미수행 | −80 |
| 고유 루틴 단계 첫 클리어, 당일 필수 충족 | +20 |

레벨과 레벨업 막대는 표시하지 않습니다. 일별 점수와 필수 운동 달성 여부는 유지합니다. 누적 점수는 0 미만으로 내려가지 않습니다. 같은 날 같은 종목을 여러 번 기록해도 출석 점수는 중복되지 않습니다. 당일 필수를 충족하지 않으면 추가 운동으로 감점을 상쇄할 수 없습니다. 클리어 배지는 필수 충족 여부와 별개로 기록됩니다.

## 가상 체중과 운동 효과

시작 체중과 목표 체중만 입력합니다. 이후 실제 체중 입력은 없습니다. 최근 기록에 따라 가상 체중과 목표까지 예상 기간·도달일·민감도 범위를 표시합니다.

이 값은 **운동 에너지 환산치**입니다. 식사와 평소 활동으로 시작 체중이 유지되고 있었으며 기록한 운동은 새로 추가했다는 가정입니다. 이미 하던 운동이 식사 유지량에 포함됐다면 그 운동량을 다시 빼는 것은 과대 추정입니다.

- 순소모 kcal = `(MET − 1.3) × 현재 가상 체중 × 3.5 / 200 × 실제 운동 분`.
- 운동을 하지 않았다면 했을 가벼운 활동 1.3 MET를 차감합니다. 이는 앱의 가정값입니다.
- 맨몸운동은 3.8/7.5 MET, 배드민턴은 5.5/7/9 MET. 러닝은 기록한 속도와 가장 가까운 MET 구간.
- 맨몸운동 실제 동작 시간은 직접 입력할 수 있으며, 미입력하면 `총횟수 × 3초`로 추정합니다. 총시간이 있으면 이를 넘지 않도록 제한. 휴식시간은 고강도 운동으로 더하지 않습니다.
- 가상 체중 변화는 `순소모 / 7700` kg. 매일 가상 체중 감소에 따라 다음 운동의 소모량도 감소합니다.
- 7일 이상 마감된 기록이 쌓이면 최근 최대 28일 평균(무운동일 포함)으로 예상 기간 계산. 미래에도 체중 비례로 소모가 감소한다고 가정합니다.
- 범위는 소모량 ±30%의 시나리오 차이이며 통계적 신뢰구간이 아닙니다. 10년을 초과하거나 운동량이 없으면 예상일을 산출하지 않습니다.
- 대사 적응, 수분 변화, 근육 증가, 식욕 보상은 계산하지 않습니다. NIH의 동적 체중 모델 구현이 아니며 실제 감량·도달일을 보장하지 않습니다.

운동 효과는 관측 가능한 누적 횟수·세션 최고 횟수·첫 세트 최고·러닝 거리·페이스·배드민턴 운동 시간으로 정량화합니다. 근육량이나 체지방률 증가/감소는 임의로 만들어내지 않습니다.

## 검증

```bash
python -m unittest discover -s tests -v
```

기본 15개 및 저장소 경로 추가 검사: 04:00 경계, 필수 조합, 감점·추가 점수, 중복 점수 방지, 수동 클리어, 가상 에너지 재계산, 휴식시간 제외, 예상 기간 평균, 입력 검증, 저장 충돌, 재시작 후 보존, 외부 Origin 요청 차단.

브라우저에서 초기 설정, 풀업 기록·클리어 후 다음 주차 이동, 푸쉬업 주차·Day·난이도 전환, 목표 미달 기록의 필수 운동 충족, 다크모드 전환을 확인했습니다. Supabase 접속 정보가 아직 제공되지 않아 실제 Supabase 원격 연결 및 Render 계정 배포는 검증하지 않았습니다. Postgres 경로는 드라이버 모의 검사로 SQL 매개변수·동시 수정 처리·접속 보안을 확인했습니다. 모바일 실기기 동작은 아직 검증하지 않았습니다.

배포 연결 문서: https://supabase.com/docs/guides/database/connecting-to-postgres

코발트 블루 포인트 적용(라이트 #0047AB, 다크 #6C9EFF). 영문 장식 문구·섹션 번호·하단 슬로건·레벨 표시를 제거하고, 기능에 필요한 제목과 입력 안내만 유지했습니다.

## 여수 날씨 면제·월 2회 휴가

- 여수 기준 좌표 34.7604, 127.6622. 개인 비상업용 무료 Open-Meteo API를 사용하며 API 키는 필요 없습니다.
- 한국 시간 00:00~23:59 중 비/눈이 한 번이라도 확인되면 해당 유산소일의 의무를 면제합니다. 오늘의 아직 오지 않은 시간대 예보로 미리 면제하지 않습니다. 맨몸운동일 풀업·푸쉬업 의무는 유지합니다.
- 자료는 기상 관측소 실측이 아닌 시간별 예보/재분석 모델입니다. 비/눈이 잠깐 내렸어도 모델이 포착하지 못할 수 있습니다. 0보다 큰 강수량 또는 적설량이 있으면 면제합니다.
- 최근 14일과 오늘은 Forecast API, 그 이전은 Archive API를 사용합니다. 최초 과거 조회는 시간이 걸릴 수 있습니다.
- 날씨 결과는 DB에 보존하고 프로세스에서 30분 캐시합니다. 이미 비/눈으로 면제한 날은 모델 수정으로 면제를 취소하지 않습니다.
- 조회 실패·불완전 자료는 맑은 날로 간주하지 않습니다. 해당 유산소일의 미수행 감점은 확인 때까지 보류하며, 자료가 확인되면 과거 점수를 재계산합니다.
- 월 2회 휴가. 시작일~오늘 중 선택, 이월 없음. 취소하면 그 달 횟수가 복원되고 점수가 재계산됩니다. 메모 선택 입력.
- 휴가 자체에는 점수나 가상 감량이 없습니다. 휴가일에도 운동 기록 가능. 필수 조합을 채우면 기존 점수, 부분 맨몸운동은 종목당 50점·추가 유산소는 종목당 25점입니다.
- 휴가 사용은 날씨 면제와 별개로 1회를 소모합니다. 이미 날씨 면제인 유산소일에는 휴가를 아낄 수 있습니다.
- 주간 캘린더에 완료/날씨/휴가/미달·대기 구분. 날짜를 누르면 해당 운동 기록으로 이동합니다.
- 지난주 비교는 월요일부터 오늘 요일까지와 지난주 동일 기간을 비교합니다. 기록된 시간은 미입력 시간을 0으로 취급합니다.
- 다음 루틴 목표를 현재 위치 아래 표시합니다. 마지막 단계는 마지막 단계로 안내합니다.
- 카드·페이지 등장, 숫자 카운트, 완료 체크, 진행 막대, 저장 강조, 클리어 파티클, 버튼 반응, 모달·테마 전환 애니메이션. 기기의 prefers-reduced-motion 설정 시 비활성화합니다.
- 미리보기 HTML도 동일 기능을 포함합니다. 날씨 조회에는 인터넷 연결과 브라우저의 외부 요청 허용이 필요합니다. 프리뷰 기록/날씨 캐시는 해당 브라우저에만 저장됩니다.

## 종목별 성장 추이

대시보드의 기존 체중 그래프에서 종목·지표·기간을 전환합니다. 최근 30일/90일은 오늘을 포함하며 전체 기간 선택도 가능합니다.

| 종목 | 지표 |
|---|---|
| 가상 체중 | 일별 체중 |
| 풀업·푸쉬업 | 일별 총횟수, 그날 모든 세트 중 최고 횟수 |
| 러닝 | 일별 총거리, 총시간, 거리 가중 평균 페이스(총시간/총거리) |
| 배드민턴 | 일별 운동 시간 합계 |

운동 그래프는 기록한 날짜만 표시합니다. 미기록일을 0으로 만들지 않으며 날짜 간 실제 간격을 반영합니다. 최신 값과 선택 기간 첫 기록 대비 차이를 보여주고, 페이스는 낮을수록 빠르다고 안내합니다. 점에 마우스를 올리거나 날짜별 수치표를 열어 정확한 값을 확인할 수 있습니다. 표는 최근 100개, 그래프는 선택 기간 전체를 표시합니다.

추이 집계 검사: `node tests/test_trends.cjs` — 같은 날 합산, 최고 세트, 거리 가중 페이스, 배드민턴 시간, 빈 기록, 30일 경계, 체중 등 7개 확인. 기존 Python 검사 33개도 통과했습니다.
